# Purpose

This document defines the mandatory rules that govern every activity within the Raghad World project.

These rules apply to all contributors, including AI assistants, developers, designers, reviewers, and future team members.

Failure to follow these rules may lead to inconsistent decisions, unnecessary rework, and reduced product quality.

---

# Core Principles

## 1. Strategy Before Design

No visual design work should begin before the related business strategy has been approved.

---

## 2. Design Before Code

No implementation should begin before the UX, UI, and specifications have been approved.

---

## 3. Documentation Before Implementation

Every feature must be documented before development starts.

If documentation does not exist, implementation must not begin.

---

## 4. Official Documentation First

Easy Orders official documentation is the only trusted source for platform capabilities.

No undocumented API, hook, component, or behavior may be assumed.

---

## 5. Evidence Over Opinion

Business decisions must be supported by research, user experience principles, conversion optimization practices, analytics, or official documentation.

Personal preference is never enough.

---

## 6. Build Trust First

Every feature, page, component, or interaction should help achieve at least one of the following:

- Build trust
- Reduce purchase anxiety
- Improve usability
- Increase conversions

If it achieves none of these goals, its value should be questioned.

---

## 7. Mobile First

All experiences must be designed for mobile users first and then enhanced for larger screens.

---

## 8. Performance Matters

Visual quality must never compromise performance.

Fast loading pages are mandatory.

---

## 9. Accessibility Matters

Interfaces should be usable by the widest possible range of users.

Accessibility is considered part of product quality.

---

## 10. Reusable Components

Every UI component should be reusable whenever possible.

Avoid duplicate implementations.

---

## 11. Framework Freeze Principle

The governance framework is now considered stable.

New:
- governance systems
- workflow stages
- documentation layers
- templates
- indexes
- management systems

must NOT be introduced unless a demonstrated operational problem exists.

Preference must always be given to:
- Simplicity
- Consistency
- Maintainability

over theoretical completeness.

Framework evolution becomes exception-based rather than idea-based.

---

## Documentation Rules

Every important decision must become documentation.

No undocumented feature should exist.

Documents are living assets and should be updated whenever decisions change.

---

## Decision Rules

Large decisions require discussion before implementation.

Approved decisions must be recorded as ADRs (Architecture Decision Records).

Rejected proposals should remain documented for future reference.

---

## Research Rules

Competitor analysis must focus on learning rather than copying.

Best practices should always be adapted to fit the Raghad World brand.

---

## Branding Rules

The brand always comes before short-term sales tactics.

No dark patterns.

No fake urgency.

No fake reviews.

No misleading discounts.

Customer trust is more valuable than short-term conversions.

## Repository Rules

The repository is the single source of truth.

Business decisions belong in documentation.

Implementation belongs in code.

Research belongs in research documents.

Temporary notes should never replace documentation.

---

## Final Rule

When there is uncertainty:

Stop.

Research.

Document.

Approve.

Then implement.

Never guess.
