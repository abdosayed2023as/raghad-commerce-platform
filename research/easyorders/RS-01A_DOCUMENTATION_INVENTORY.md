# Recommended Learning Roadmap

## Phase 1: Environment Setup
1. **Custom Themes > Getting Started**
   *Reason*: Provides the overarching mental model of what a Custom Theme is in this ecosystem.
2. **Custom Themes > CLI Development**
   *Reason*: Required to establish the developer workflow before writing code.

## Phase 2: Theme Foundations
3. **Custom Themes > Theme Settings & Palette**
   *Reason*: Establishes global parameters, rules, and CSS variables for the entire system.
4. **Custom Themes > Dynamic Theme Data**
   *Reason*: Details the schemas and models that feed data to the interface components.

## Phase 3: Core UI
5. **Custom Themes > Sections (All)**
   *Reason*: The core components that must be built to assemble the interface.

## Phase 4: Rendering & Interactivity
6. **Custom Themes > Liquid Reference**
   *Reason*: Defines the syntax used to weave Dynamic Theme Data into the Sections.
7. **Custom Themes > Events Reference**
   *Reason*: Defines how to interact with the platform natively through JavaScript.

# Potential Ambiguities

- **Page Templates Structure**: The `Sections` category breaks components down into Layout, Product, Home, and Utility, but it does not specify how top-level "Pages" (e.g., cart page, search page) are structured as holistic templates.
- **Asset Pipeline Context**: The `events-reference` implies JavaScript usage, and `upload-assets` exists in the merchant Dashboard, but there is ambiguity regarding how the CLI handles bundling or serving CSS/JS assets during development.
- **Organizational Ambiguity**: The Dashboard documentation contains a flat `Overview` page sitting outside of any specific category, and the Public API documentation lists endpoints flatly rather than under distinct resources.

# Potential Documentation Gaps

- **Redundant API Pages**: There is a `public-api` section under Dashboard > Store Management, despite the existence of a separate Public API Documentation domain.
- **Missing Asset Pipeline Guide**: No dedicated documentation within Custom Themes explicitly outlines the asset pipeline architecture (compilation, minification, serving).

# Research Questions

- How does the CLI handle compiling and bundling static assets like JavaScript and CSS?
- Do the `Layout`, `Product`, `Home`, and `Utility` sections represent the entirety of the UI rendering engine, or are there hidden page templates?
- Can we inject custom API calls into the theme using JavaScript, or is data retrieval strictly limited to Liquid rendering?
- How are non-product pages (e.g., About Us, Contact) templated within the Custom Theme paradigm?

# Risks

- Misunderstanding the difference between a `Section` and a full `Template` could cause architectural rework.
- Lack of clarity on the asset pipeline might lead to suboptimal frontend performance if assets cannot be bundled effectively via the CLI.
