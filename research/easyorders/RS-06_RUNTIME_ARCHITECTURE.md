## Facts
- The platform uses LiquidJS, a JavaScript implementation of the Liquid template language, to render custom themes.
- Each section (`.liquid` file) acts as an independent template. 
- The platform injects store data (e.g., `theme_data`, `product_theme_data`) into the LiquidJS context, which outputs an HTML string.
- The theme's `style.css` and `script.js` are loaded globally across all pages.
- The Easy Orders storefront operates as a Single Page Application (SPA) built with React.
- The HTML generated by LiquidJS for each section is injected into specific "Section Containers" managed by the React application.
- The React SPA automatically intercepts clicks on internal `<a>` links (same-origin, same-domain) to handle routing. External links, `target="_blank"`, and links with a `download` attribute bypass this interception.
- Custom themes communicate user intent to the platform by dispatching standard `CustomEvent` objects from within the injected HTML.
- Events MUST be dispatched with `{ bubbles: true }`. 
- The React app does not attach listeners directly to theme elements; it attaches a `useLiquidEvents` listener to the parent Section Container.
- Contextual data (e.g., a product ID for `quick-add`) is passed via the `detail` property of the `CustomEvent`.

## Observations
- The primary boundary between the Custom Theme (developer-controlled HTML/JS) and the Platform (React app) is the DOM Event System.
- Theme-provided JavaScript in `script.js` executes globally in the browser environment, allowing scripts to query DOM elements and attach their own listeners to programmatically dispatch bubbling `CustomEvent`s.
- Because `script.js` executes in an SPA environment where sections may mount/unmount via routing, scripts likely need to rely on event delegation or handle dynamic DOM updates appropriately (though explicit documentation on mutation observers vs. direct binding was absent).

## Insights
- A custom theme operates essentially as an injected data payload (HTML string + global JS/CSS) rather than a first-class React component.
- The storefront's event-driven architecture strictly decouples state management from the theme, offloading all complex logic (cart operations, navigation) to the React SPA via standard DOM event bubbling.

## Business Impact
- This decoupled architecture enables theme developers to focus entirely on visual presentation, accelerating the creation and modification of merchant themes without requiring advanced platform backend knowledge.

## Engineering Impact
- Theme developers must ensure every interactive trigger strictly uses DOM Event bubbling. They cannot directly invoke storefront state functions or React context.
- Development tooling must account for the SPA lifecycle, ensuring any complex JavaScript integrations (like external slider libraries) are robust against dynamic DOM insertions.

## Terminology
- **LiquidJS**: A JavaScript port of the Liquid template language used by the platform to compile `.liquid` files.
- **SPA (Single Page Application)**: A web application that interacts with the user by dynamically rewriting the current web page with new data from the web server.
- **Section Container**: The parent React component in the storefront SPA that wraps injected Liquid HTML and listens for bubbling custom events via `useLiquidEvents`.
