# Audit Toolkit V1.9.1 (AT-01..AT-09)

A stateless, configuration-driven, vendor-independent website evidence collector, metrics parser, rule evaluator, finding builder, context packager, AI report builder, audit comparator, developer specification generator, and GitHub task payload generator built with Node.js, Playwright, and Google Lighthouse.

---

## 1. Purpose

**Audit Toolkit V1** operates as a multi-tier architectural pipeline:
1. **AT-01 Evidence Collector**: Automatically gathers reproducible, objective, raw evidence artifacts (screenshots, HAR, console logs, Lighthouse reports).
2. **AT-02 Structured Metrics Analyzer**: Parses raw evidence into a normalized machine-readable metrics document `analysis.json`.
3. **AT-03 Rule Engine**: Evaluates `analysis.json` metrics against centralized threshold rules to produce `rules.json`.
4. **AT-04 Finding Builder**: Transforms failed/skipped rules into traceable, structured findings in `findings.json` using dynamic evidence ID generation.
5. **AT-05 Context Builder**: Assembles all previous outputs into a single, normalized package `audit-package.json`.
6. **AT-06 AI Report Builder**: Consumes **ONLY** `audit-package.json` to generate a versioned, traceable audit report `report.json`.
7. **AT-07 Audit Comparator**: Standalone module that consumes **ONLY** structured contracts (`audit-package.json`, `report.json`) across two runs to produce a deterministic `comparison.json`.
8. **AT-08 Specification Generator**: Consumes **ONLY** `report.json` (and optional `comparison.json`) to convert recommendations into machine-readable developer specifications `specifications.json`.
9. **AT-09 GitHub Task Generator**: Consumes **ONLY** `specifications.json` to generate deterministic GitHub issue payloads `github-issues.json` preserving complete `Specification → Finding → Evidence` traceability.

## 2. Requirements

- **Node.js**: LTS version (v18.x, v20.x, or v22+)
- **Operating System**: Windows (primary), macOS, or Linux
- **Dependencies**: Completely free, open-source, and offline-capable after installation.

## 3. Installation

Navigate to the `tools/audit-toolkit` directory and install dependencies:

```bash
cd tools/audit-toolkit
npm install
node node_modules/playwright/cli.js install chromium
```

---

## 4. Configuration (`audit.config.json`)

Configure targets and report provider:

```json
{
  "target": "https://raghadkids.com",
  "environment": "production",
  "reportProvider": "mock",
  "outputDir": "output",
  "maxRetries": 3
}
```

The `reportProvider` field is configuration-driven (`"mock"` by default) allowing future providers (e.g. `claude`, `openai`, `gemini`, `ollama`) to be plugged in seamlessly without changing the pipeline or schema.

## 6. Commands

Run main pipeline end-to-end (AT-01..AT-06, AT-08, AT-09):

```bash
npm run audit
```

Run standalone **AT-07 Audit Comparator**:

```bash
npm run compare
```

Run standalone **AT-08 Specification Generator**:

```bash
npm run spec
```

Run standalone **AT-09 GitHub Task Generator**:

```bash
npm run github
```

## 7. Standardized Schema Versioning

Every contract generated by the toolkit includes `schemaVersion: "1.0.0"`:
- `manifest.json` (`schemaVersion: "1.0.0"`)
- `analysis.json` (`schemaVersion: "1.0.0"`)
- `rules.json` (`schemaVersion: "1.0.0"`)
- `findings.json` (`schemaVersion: "1.0.0"`)
- `audit-package.json` (`schemaVersion: "1.0.0"`)
- `report.json` (`schemaVersion: "1.0.0"`, `reportVersion: "1.0.0"`)
- `comparison.json` (`schemaVersion: "1.0.0"`)
- `specifications.json` (`schemaVersion: "1.0.0"`)
- `github-issues.json` (`schemaVersion: "1.0.0"`)

---

## 8. Issue Identity

GitHub issues are uniquely identified internally using the deterministic `fingerprint` field (`Rule ID` + `::` + `Target Page Slug` + `::` + `Viewport`).
This enables future synchronization, duplicate detection, and issue updates without relying on issue titles.
